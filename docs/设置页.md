# acpx-bridge 设置页

本插件在 dsh 左下角 **设置（Settings）** 面板里注册一个导航项 **acpx-bridge**（`settings.section`，id `acpx-bridge`，order 25），点开是一整页设置。同一份状态也以简短摘要卡的形式出现在 **插件管理页**（`plugins.item`），卡片只显示状态、模型计数和「去设置页」的指引。

- 页面首次挂载时 `GET /api/acpx-bridge/state` 拉一次全量状态；
- 之后只在 **写操作成功后**、以及 **`document.visibilitychange` 回到可见** 时刷新一次；
- 没有任何轮询 / WebSocket。

## 界面结构

页面按 6 个分组呈现。第 1 组固定常显，其余 5 组都可以折叠；折叠状态写在
`localStorage` 的 `acpx-bridge:settings:groups`（JSON：`{ [组 id]: boolean }`），
模型分组里每个命令工具（agent）的二级折叠写在 `acpx-bridge:settings:agents`。
localStorage 不可用时降级为「按默认展开」，并在控制台记录原因。

| # | 分组 | 默认 | 内容 |
|---|---|---|---|
| 1 | 运行概览 | 常显（不可折叠） | 状态徽标（可用 / 未授权 / acpx 缺失）、生效端点 + 来源标签（页面覆盖 / 配置 / 环境变量 / 默认）、密钥状态、模型计数（已启用 n / 共 m）、acpx 路径与版本 |
| 2 | 授权：模型端点 | 展开 | 密钥输入（`type=password`，每次打开为空）+ 保存/清除、端点地址 + 恢复默认、测试连接、凭据引用名 `ACPX_BRIDGE_API_KEY` |
| 3 | 模型显示 | 展开 | 已启用 n / 共 m、全部启用 / 全部停用、按 agent 二级分组的模型行（显示名 + 原始 id + 开关） |
| 4 | 命令工具状态 | 折叠 | acpx 路径 / 版本 / 状态 + 重新检测、每个 agent 的模型数与状态（有真实模型 / 仅占位）、登录命令 + 复制按钮 |
| 5 | acpx_delegate 默认参数 | 折叠 | 默认 agent / 模式 / 权限 / 输出格式 / 超时毫秒 |
| 6 | 诊断 | 折叠 | 插件版本、provider 路由名、profile 条目 id、wire 模型映射、刷新模型列表、重置本页设置为默认（二次确认）、文档链接 |

状态徽标的判定顺序：

1. `acpx --version` 探测失败 → **acpx 缺失**；
2. 密钥未配置 → **未授权**；
3. 否则 → **可用**。

## 每个开关的作用与生效时机

| 操作 | 作用 | 生效时机 |
|---|---|---|
| 保存 / 清除密钥 | 写入 / 删除凭据库里的 `ACPX_BRIDGE_API_KEY` | 立即。下次模型调用或测试连接重新解析密钥（适配器每次调用都重算连接，不缓存） |
| 端点地址 / 恢复默认 | 写 `prefs.baseURLOverride` | 立即。下一次请求使用新端点 |
| 模型开关 / 全部启用 / 全部停用 | 写 `prefs.disabledModels` | 立即（乐观更新）。保存成功后 Host 广播 `llm/adapters-updated`，模型选择器重新拉取；`listModels` 过滤掉停用项，`resolveModel` 对停用模型抛 `MODEL_DISABLED`，`acpx_delegate` 执行时也会拒绝 |
| 默认 agent / 模式 / 权限 / 输出格式 | 写 `prefs.defaults.*` | 立即。只影响**未显式传参**的 `acpx_delegate` 调用 |
| 默认超时毫秒 | 写 `prefs.defaults.timeoutMs` | 输入 **debounce 500ms** 后保存；夹到 `[60000, 3600000]` |
| 重新检测（acpx） | 立即跑一次 `acpx --version` | 立即，结果就地更新概览与第 4 组 |
| 测试连接 | 用**生效端点 + 生效密钥**发一次最小 `chat/completions`（`max_tokens=8`、`stream=false`、15s 超时） | 立即，结果就地显示成功（延迟 ms / 模型 id）或失败（HTTP 状态码 + 错误摘要） |
| 刷新模型列表 | `PUT /prefs` 空 patch，触发 Host 广播 | 立即，模型选择器重新拉取 |
| 重置本页设置为默认 | 点一次变成「确认重置？」，再点才执行 | 立即（`{ "reset": true }`） |

失败处理：开关是乐观更新，写入失败会**回滚**到写入前的状态，并在页面顶部显示错误条（含 Host 返回的错误摘要）。

## 密钥：存放位置与约定

- 密钥**只**写入本机凭据库（dsh 的 credential seal，默认落在 `$DSH_HOME/.credentials.yaml`，由 `@deepseek-ai/dsh-credentials-local` 管理），引用名固定为 `ACPX_BRIDGE_API_KEY`。
- **绝不写进任何设置文件**：既不会写进 profile 的 `cordis.patch.yml`（那会丢注释，也可能把密钥固化成文件内容），也不会写进本插件自己的 `prefs.json`。
- **绝不回传给浏览器**：`GET /state` 只返回 `{ configured, source, writable }`，没有任何接口能读出密钥明文；页面输入框每次打开都是空的。
- 来源判定：
  - `source=file` → 凭据库里的值，可在本页写入（绿色「已配置」+ 清除按钮）；
  - `source=env`（或 `config`）→ 由进程环境 / cordis 配置注入，页面输入框与保存按钮**禁用**，并提示「当前由环境变量 ACPX_BRIDGE_API_KEY 提供，删除该环境变量后才能在这里写入」；
  - 未配置 → 显示「未配置」，等待写入。
- Host 侧解析顺序：`Config.apiKey`（通常由 `!!js process.env.ACPX_BRIDGE_API_KEY` 注入）> 凭据库 `resolve('ACPX_BRIDGE_API_KEY')` > 空。Config 层存在时本页写入不会生效，所以此时页面明确禁用写入。

## 持久化文件

插件自有的偏好文件：`<DSH_HOME>/storages/acpx-bridge/prefs.json`（`DSH_HOME` 为空时用 `~/.dsh`）。

```json
{
  "version": 1,
  "disabledModels": [],
  "displayNames": {},
  "baseURLOverride": "",
  "defaults": { "agent": "", "mode": "exec", "approve": "reads", "format": "quiet", "timeoutMs": 600000 },
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

- **原子写**：先写同目录随机后缀 `.tmp`（`wx` 独占创建、`0600`），再 `rename` 覆盖目标；目录 `0700`、文件 `0600`；崩溃时读到的要么是旧完整内容，要么是新完整内容。
- **串行队列**：所有写入排队执行，`mergePrefs` 在队列内基于最新提交值合并，两个并发开关不会互相覆盖。
- **校验**：`version` 不等于 1 时整份丢弃回默认；未知字段丢弃；类型不符丢弃；`disabledModels` 只保留非空字符串并去重；`displayNames` 的空串值会删键；`timeoutMs` 夹到 `[60000, 3600000]`；`baseURLOverride` 只接受不带内嵌账号的 http(s) 地址。
- 文件损坏（非 JSON）时记一条 warn 并用默认值启动，插件不会因为偏好文件坏掉而挂载失败。

## HTTP 接口

全部挂在 dsh 自己的端口上（`ctx.webServer.register`，`kind: 'exact'`，包在 `ctx.effect` 里；没有独立端口）。

### `GET /api/acpx-bridge/state`

一次返回页面所需的全部数据（**不含任何密钥明文**）：

```json
{
  "ok": true,
  "version": "0.1.0",
  "provider": "acpx-bridge",
  "entryId": "acpx-bridge",
  "endpoint": { "effective": "http://…/v1", "source": "prefs", "fallback": "http://…/v1" },
  "credential": { "ref": "ACPX_BRIDGE_API_KEY", "configured": true, "source": "file", "writable": true },
  "acpx": { "bin": "acpx", "path": "/usr/local/bin/acpx", "version": "0.22.0", "ok": true, "error": "" },
  "catalog": [
    { "agent": "opencode", "models": [
      { "id": "my/opencode/xxx", "name": "acpx/xxx", "placeholder": false, "enabled": true }
    ] }
  ],
  "counts": { "total": 5, "enabled": 3 },
  "prefs": { "…整个 prefs…": "同上" },
  "wireModels": {},
  "notes": { "configSource": "profile cordis 配置（cordis.patch.yml / --patch）", "docs": "docs/设置页.md" }
}
```

`endpoint.source` 为 `prefs`（页面覆盖）/ `config`（cordis 配置）/ `env`（环境变量）/ `default`。
`counts` 按**去重后的模型 id** 统计，与模型选择器里的条目数一致（多个 agent 都写 `default` 时只算 1 个）。

### `PUT /api/acpx-bridge/prefs`

请求：`content-type: application/json`，body 为**局部** patch：

```json
{ "disabledModels": ["default"], "defaults": { "timeoutMs": 300000 } }
```

- 顶层键存在即整体替换；`defaults` 按键合并（改超时不会重置其它默认参数）；
- `{ "reset": true }` 把整份文档重置为默认值（控件标记，不落盘）；
- `{}` 是合法的空 patch：什么也不改，但会触发一次模型列表广播（「刷新模型列表」按钮就是这么实现的）。

响应：`{ "ok": true, "prefs": { …提交后的完整 prefs… }, "state": { …同 GET /state… } }`。
写成功后 Host 广播 `llm/adapters-updated`（本 dsh 版本真正转发给客户端的事件，模型选择器据此重新拉取），同时附带 `llm/models-updated` 作为任务级兼容名。

### `POST /api/acpx-bridge/verify`

无 body（有 body 也不会被读取）。用**生效端点 + 生效密钥**发一次 `chat/completions`：`max_tokens=8`、`stream=false`、超时 15s。

```json
{ "ok": true, "latencyMs": 842, "model": "gs/deepseek-flash-deepseek.com", "status": 200, "error": "" }
```

失败时 `ok=false`：`status` 是 HTTP 状态码（网络层失败为 0），`error` 是脱敏后的一行摘要（去掉 `Bearer …`、`sk-…` 与 32 位以上疑似令牌）。

### `POST /api/acpx-bridge/acpx-check`

无 body。立即执行 `acpx --version`（可执行名取 `process.env.ACPX_BIN`，默认 `acpx`）：

```json
{ "ok": true, "path": "/usr/local/bin/acpx", "version": "0.22.0", "error": "" }
```

未安装时 `ok=false`，`error` 说明「未找到可执行文件」。

## 安全措施

- **只接受同源请求**：`Host` 缺失或不可解析 → 403；有 `Origin` 时其 `host` 必须与 `Host` 完全一致，否则 403；`sec-fetch-site: cross-site` 直接拒绝。GET/PUT/POST 四个路由都过这道闸。
- **写入接口要求 `content-type: application/json`**（允许带 `; charset=…` 参数），否则 415。
- **请求体上限 64 KiB**，超限 413。
- **不发 CORS 头**：没有任何 `Access-Control-Allow-Origin`，异源页面既读不到响应也无法预检通过。
- **错误形状固定**为 `{ "error": { "code": "…", "message": "…" } }`，message 不含任何密钥或完整上游响应。
- 响应带 `cache-control: no-store` 与 `x-content-type-options: nosniff`。

## 模型启停如何影响选择器与工具

- `AcpxBridgeAdapter.listModels()` 过滤 `prefs.disabledModels`，因此**模型选择器里真的会少掉**被停用的条目；`resolveModel()` 对被停用模型抛 `LlmError('MODEL_DISABLED')`。
- 广播 `llm/adapters-updated` 后，客户端（设置页/选择器）立刻重新拉取，无需刷新页面。
- `acpx_delegate` 的参数 `enum` 由注册时的配置决定（平台不允许热更新 enum），所以 enum 里仍可能出现已停用的 id；**执行时会挡**：返回 `ok:false` + `diagnostic`（提示去设置页重新启用）。
- `acpx_agents` 的输出逐模型标注 `enabled` / `placeholder`，并给出每个 agent 的 `enabledCount / totalCount`。
- 全部停用时页面给红色警示：模型选择器中将不再出现 acpx-bridge 的模型。

## 默认参数优先级

`acpx_delegate` 每个参数独立取值，优先级从高到低：

1. 模型调用时显式传入的参数（`agent` / `mode` / `approve` / `format` / `timeoutMs`）；
2. 设置页 `prefs.defaults.*`；
3. 代码里的历史常量（`agent` = 配置里的第一个 agent，`mode=exec`、`approve=reads`、`format=quiet`、`timeoutMs=600000`）。

`prefs.defaults.agent` 若已不在当前配置的 agent 列表里（配置改过），自动回落到第一个 agent。默认 `agent` 为空串表示「不指定，用第一个」。

## 相关文件

- `src/prefs.js` — 校验 / 合并 / 过滤 / 显示名 + 原子文件存储
