# 命令工具授权（7 个平台）

设置页第 4 组「命令工具授权」把 7 个本机已安装平台 CLI 的授权搬到了页面上：
`kimi` · `trae` · `opencode` · `qwen` · `codebuddy` · `deepseek-harness` · `antigravity`。

设计前提（都不需要用户理解，只解释为什么这样实现）：

- **只做本机实际安装的 7 个**，不是 acpx 支持的全部 30+ agent。
- **探测只读**：只跑各平台自己的「查状态」命令，绝不写文件、绝不跑 `acpx <agent> exec`（那会花钱）。唯一的例外是 `kimi login`——它是 Kimi 唯一能问出授权状态的入口，已授权时只打印一行并退出。
- **密钥明文落盘到各平台自己的配置文件**（可接受），但页面任何响应、日志、SSE 帧都只出现掩码后的末四位。

## 1. 状态判定（实测命令与正则）

| 平台 | 探测命令 | 判定 | 状态 |
|---|---|---|---|
| Kimi | `kimi login` | 输出含 `Logged in` → 已授权；含设备码/链接（`https://…` 或 `XXXX-XXXX`）→ 未授权 | `authorized` / `unauthorized` |
| Trae | `traecli login status` | `Not logged in` → 未授权；`logged in` / `authenticated` → 已授权 | `authorized` / `unauthorized` |
| OpenCode | `opencode auth list` | `0 credentials` → 未授权；`N credentials`（N≥1）→ 已授权 | `authorized` / `unauthorized` |
| Qwen | 读 `~/.acpx/config.json` | `agents.qwen.argv` 里有 `--openai-api-key <非空>` → 已授权 | `authorized` / `unauthorized` |
| CodeBuddy | 无 | 无 login 子命令，首启是交互式 TUI，本机无可判定凭据文件 | `unknown` |
| DeepSeek Harness | 无 | 本地 `dsh --profile acp`，免授权 | `no-auth` |
| Antigravity | 无 | `/usr/local/bin/agy_acp_server.par` 一跑就 SIGILL | `unavailable` |

判定顺序固定为 **未授权 → 已授权 → 待确认 → 超时 → 未知**：`Not logged in` 里含有 `logged in`，负向答案必须先命中。

每个平台还会跑一次 `<bin> --version` 拿版本；找不到可执行文件时 `installed=false`、状态 `unavailable`、不给任何动作按钮。Antigravity 的详情原文保留 CLI 输出：

```
FATAL ERROR: This binary was compiled with avx enabled, but this feature is not available on this processor (go/sigill-fail-fast).
```

- 7 个平台并发探测，单个 8 秒超时，互不影响；
- 结果进程内缓存 30 秒，`GET /api/acpx-bridge/agents?force=1` 绕过（页面右上「全部检测」）；
- 任一输出都先 `stripAnsi` 再截断（单条 detail ≤ 2KB，整包 ≤ 32KB）。

## 2. 四类动作

| 动作 | 平台 | 说明 |
|---|---|---|
| **设备码登录（login job）** | kimi、trae | 起一个子进程，输出实时流到页面；trae 还要把回调 URL 粘回输入框（写 stdin） |
| **API Key（写配置文件）** | opencode、qwen | 页面表单写入，写前备份、写后回读校验，失败回滚 |
| **交互式（只复制命令）** | codebuddy | 页面无法驱动 TUI，只给「复制登录命令」`codebuddy` |
| **免授权 / 不可用** | deepseek-harness、antigravity | dsh 只给「测试」；antigravity 只显示不可用原因 |

公共动作：

- **[测试]**：`acpx <agent> exec "ping" --format quiet`，**真实调用一次子 agent，可能产生费用**，所以页面先弹 `window.confirm` 二次确认；同一平台 60 秒冷却（429），超时 120 秒，stdout/stderr 各截 4KB。
- **[退出]**：只出现在有 logout 子命令的平台（trae → `traecli logout`，opencode → `opencode auth logout <provider>`）。Kimi / Qwen / CodeBuddy / dsh / antigravity 没有 logout，接口返回 400 `logout-not-supported`。

## 3. 登录 job 与 SSE 协议

`POST /api/acpx-bridge/agents/login`（body `{ agent, region? }`，`region` 只对 Kimi 生效：`mainland-cn` / `global`）→

```json
{ "ok": true, "jobId": "<uuid>", "agent": "kimi", "argv": "kimi login", "startedAt": 1712345678901 }
```

同一平台已有运行中的 job 时返回 **409** 并带上现有 `jobId`（页面直接连上去，不报错）；全局最多 **3 个**并发 job，超出返回 **429**。

订阅输出：`GET /api/acpx-bridge/agents/login/events?agent=<id>&job=<jobId>`，`text/event-stream`，帧顺序固定：

```
event: snapshot
data: {"jobId":"…","agent":"kimi","argv":"kimi login","startedAt":…,"seq":0,"text":"","done":false,"exitCode":null,"signal":null,"timedOut":false,"links":[]}

event: chunk
data: {"seq":1,"text":"Go to https://auth.kimi.test/device?code=ABCD-1234\n"}

event: exit
data: {"jobId":"…","agent":"kimi","exitCode":0,"signal":null,"done":true,"timedOut":false,"durationMs":8123,"links":["https://auth.kimi.test/device?code=ABCD-1234"]}
```

- `snapshot` 是连上后的第一次补发：`text` 是环形缓冲区里的全部内容（保留最后 64KB），`seq` 是最新序号，`links` 是已抓到的链接；
- `chunk` 是之后每条新输出，`seq` 严格递增，前端据此丢弃重复；
- `exit` 之后服务端关闭流；
- 每 15 秒一个 `: ping` 注释行，防代理把空闲连接掐掉；
- 断开（页面关闭 / 切分组 / `request.signal` abort）会 **kill 该 job**，避免留下等输入的 CLI。

其它 job 接口：

- `POST /api/acpx-bridge/agents/login/input` body `{ agent, jobId, text }`：写 stdin（自动补 `\n`）。只允许 `pasteCallback: true` 的平台（当前只有 trae），其它返回 400 `input-not-supported`。
- `POST /api/acpx-bridge/agents/login/cancel` body `{ agent, jobId }`：SIGTERM，2 秒后 SIGKILL。

硬约束：job 5 分钟自动 kill；jobs 的 Map 在插件 `apply` 闭包里；插件卸载 `killAll()`；job id 是 `crypto.randomUUID()`，且必须属于该 agent（跨平台访问 → 404）。

## 4. 密钥写盘位置与回滚

### opencode → `~/.local/share/opencode/auth.json`

结构按 opencode dist 里的读写实现：

```json
{
  "openai": { "type": "api", "key": "<明文>" }
}
```

写入流程：读原文件（缺省 `{}`）→ 同目录 `.bak-<yyyyMMdd-HHmmss>` → 合并该 provider 的 `{ type: 'api', key }`（其它 provider 原样保留）→ `tmp-<uuid>` + rename 原子写（0600）→ 回读 `opencode auth list`，必须退出码 0 且出现 `N credentials`（N≥1）才算成功；否则把备份拷回（原本不存在的文件则删除）并返回 `{ ok:false, error }`。

移除 / 退出：`opencode auth logout <provider>`（需要 body 里带 `provider`）。

> 注：`opencode auth login` 是交互式 TUI，页面**不会**调用它。

### qwen → `~/.acpx/config.json` → `agents.qwen.argv`

```json
{
  "agents": {
    "qwen": {
      "argv": ["qwen", "--acp", "--auth-type", "openai",
               "--openai-api-key", "<KEY>", "--openai-base-url", "<BASE>", "--model", "<MODEL>"]
    }
  }
}
```

- 只改 `agents.qwen.argv`，**其它 agent（codebuddy / opencode / kiro …）和所有未知字段整体保留**；
- 写前同目录留 `.bak-<时间戳>`，`JSON.stringify(…, null, 2)` + 原子 rename，文件 0600；
- 写后重新解析回读，确认 `--openai-api-key` 后面就是刚写的值；不通过就回滚；
- 响应只回 `{ ok, configured, baseURL, model, maskedKey: "****abcd" }`；
- `POST /api/acpx-bridge/agents/key/remove` 只摘掉 `--openai-api-key` / `--openai-base-url` / `--model` 及其值，其它参数（`qwen --acp --auth-type openai`）保留。

> **明文风险提示**：`~/.acpx/config.json` 里的密钥是明文，并且 `acpx` 每次启动子 agent 都会把它作为命令行参数传下去（`ps` 可见）。这是 qwen 与 acpx 现有集成方式决定的；如介意，请改用环境变量注入并删掉这里保存的密钥。

### 其它平台

`POST /api/acpx-bridge/agents/key` 对没有 keyStore 的平台返回 404 `key-not-supported`（kimi / trae / codebuddy / dsh / antigravity）。

## 5. 限制

- **CodeBuddy 无法自动探测**：没有 login 子命令、首启是 TUI、本机 `~/.codebuddy` 里没有可判定凭据，状态只能 `unknown`。
- **Antigravity 不可用**：二进制需要 avx，本机 CPU 没有，一跑就 SIGILL；页面只显示原文，不给动作。
- **Kimi 没有 logout**：只能靠 `kimi login` 重新授权；没有 `kimi logout` 子命令。
- **并发/超时**：登录 job 最多 3 个并发、单平台 1 个、5 分钟超时；测试 60 秒冷却、120 秒超时；探测 8 秒超时、结果缓存 30 秒。
- **SSE 走 Connection 的鉴权 Fetch 承载**：断线由浏览器 `EventSource` 自动重连，重连会重新收到 `snapshot`。

## 6. 接口一览

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/acpx-bridge/agents` | 7 平台状态（`?force=1` 绕过 30 秒缓存） |
| POST | `/api/acpx-bridge/agents/login` | 起登录 job（409 复用 / 429 上限） |
| GET | `/api/acpx-bridge/agents/login/events` | SSE：`snapshot` → `chunk`* → `exit` |
| POST | `/api/acpx-bridge/agents/login/input` | 写 stdin（仅 trae） |
| POST | `/api/acpx-bridge/agents/login/cancel` | SIGTERM → 2s → SIGKILL |
| POST | `/api/acpx-bridge/agents/key` | 写密钥（opencode / qwen） |
| POST | `/api/acpx-bridge/agents/key/remove` | 移除密钥 / 凭据 |
| POST | `/api/acpx-bridge/agents/logout` | 调平台自己的 logout |
| POST | `/api/acpx-bridge/agents/test` | 真实 `acpx … exec "ping"`（花钱，需二次确认） |

> 为什么不是 `POST /agents/:id/login` 或 `DELETE`：dsh Connection 的 Fetch 契约只做**精确路径**匹配（`fetchRoutes.get(pathname)`，没有 `:param` 插值）且只允许 **GET / HEAD / POST**。所以 agent id 走 query/body，删除/取消走各自的 POST 路径。这是平台的硬约束，不是设计偏好。
